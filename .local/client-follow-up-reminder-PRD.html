Client Follow-Up Reminder

PRD, prototipe modal form, dan contoh laporan untuk fitur pengingat follow-up issue client.

1. Latar Belakang

Issue client yang butuh follow-up atau pengecekan ulang sering terlewat karena hanya diingat secara manual. Fitur ini menyimpan setiap issue dalam format baku dengan tanggal follow-up, sehingga yang jatuh tempo langsung terlihat.

2. Tujuan

  • Tidak ada issue client yang terlupa.
  • Issue yang lewat tanggal follow-up ditandai otomatis (overdue).
  • Tersedia laporan ringkas per client, modul, dan status.

3. Ruang Lingkup

Termasuk: CRUD issue, modal form, daftar dengan filter, penanda overdue, laporan ringkasan, ekspor CSV, riwayat catatan.
Tidak termasuk (tahap 1): notifikasi email/WhatsApp, integrasi tiket eksternal, SLA otomatis.

4. User Story

  • Sebagai pengguna, saya ingin mencatat issue client (client, tanggal, modul, masalah) agar tidak lupa.
  • Sebagai pengguna, saya ingin menentukan tanggal follow-up agar issue muncul sebagai pengingat saat jatuh tempo.
  • Sebagai pengguna, saya ingin menambah catatan hasil pengecekan di setiap issue agar riwayat jelas.
  • Sebagai pengguna, saya ingin melihat laporan issue yang masih terbuka dan overdue.

6. Aturan Bisnis

  • Overdue = status bukan Selesai dan followup_date lebih kecil dari hari ini.
  • followup_date tidak boleh lebih awal dari issue_date.
  • Status Selesai mengisi resolved_at otomatis dan menghilangkan penanda overdue.
  • Perubahan status dan penambahan catatan tercatat di riwayat.

7. Alur Status

Open → Perlu Pengecekan → Menunggu Client → Selesai (boleh kembali ke status sebelumnya jika issue muncul lagi).

8. Laporan

  • Ringkasan: total, overdue, jatuh tempo hari ini, selesai.
  • Filter: client, modul, status, prioritas, rentang tanggal.
  • Ekspor CSV. Urutan default: overdue dulu, lalu follow-up terdekat.

9. Kriteria Penerimaan

  • Form tidak bisa disimpan bila field wajib kosong.
  • Issue overdue tampil merah di daftar dan laporan.
  • Filter dan ringkasan laporan sesuai data.
  • Fitur terpasang sebagai menu/modul baru tanpa mengubah modul existing.

10. Catatan Integrasi ke Project Existing

  • Stack: backend Next.js (route handler / API route), frontend React, database PostgreSQL. Nama field di bawah disesuaikan dengan konvensi project.
  • Skema PostgreSQL:
    CREATE TABLE client_followups (
  id BIGSERIAL PRIMARY KEY,
  client_name VARCHAR(150) NOT NULL,
  issue_date DATE NOT NULL,
  module VARCHAR(80) NOT NULL,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  priority VARCHAR(10) NOT NULL DEFAULT 'Sedang'
    CHECK (priority IN ('Rendah','Sedang','Tinggi','Urgent')),
  status VARCHAR(20) NOT NULL DEFAULT 'Open'
    CHECK (status IN ('Open','Perlu Pengecekan','Menunggu Client','Selesai')),
  followup_date DATE NOT NULL,
  pic VARCHAR(100),
  resolved_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (followup_date >= issue_date)
);
CREATE INDEX idx_cf_status_followup ON client_followups (status, followup_date);
CREATE INDEX idx_cf_client ON client_followups (client_name);

CREATE TABLE followup_notes (
  id BIGSERIAL PRIMARY KEY,
  followup_id BIGINT NOT NULL REFERENCES client_followups(id) ON DELETE CASCADE,
  note TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

TUJUAN FITUR:

SKEMA DATABASE (PostgreSQL, sesuaikan dengan sistem migrasi project):
- client_followups: id, client_name (wajib), issue_date (date, wajib), module (wajib), title (wajib), description, priority (Rendah/Sedang/Tinggi/Urgent, default Sedang), status (Open/Perlu Pengecekan/Menunggu Client/Selesai, default Open), followup_date (date, wajib), pic, resolved_at, created_at, updated_at. Constraint: followup_date >= issue_date. Index pada (status, followup_date) dan client_name.
- followup_notes: id, followup_id (FK ke client_followups, ON DELETE CASCADE), note, created_at.
Jika project sudah punya tabel client atau modul, gunakan relasi ke tabel tersebut dan jangan membuat duplikat.

API (Next.js):
GET /api/client-followups (filter: client, module, status, priority, from, to, overdue=true; urutan default: overdue dulu, lalu followup_date terdekat), POST, GET /:id, PATCH /:id, DELETE /:id, POST /:id/notes, GET /summary (total, overdue, jatuh tempo hari ini, selesai), GET /export (CSV). Validasi input di server, kembalikan error yang jelas, dan gunakan query terparameter (tanpa SQL string concatenation).

- Overdue = status bukan Selesai dan followup_date lebih kecil dari hari ini (hitung di server dengan zona waktu Asia/Jakarta).

- Saat status menjadi Selesai, isi resolved_at otomatis; jika dibuka kembali, kosongkan.
- Setiap perubahan status dicatat sebagai catatan riwayat otomatis.
